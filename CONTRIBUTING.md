# Contributing

1. Create a branch from the default branch.
2. Keep FAQ and translation changes source-linked and reviewed.
3. Run `make validate`, `make lint` and `make test`.
4. Do not include customer data, credentials, private company documents or unverifiable metrics.
5. Explain behaviour changes in the pull request and update the changelog when appropriate.

For translation changes, include the reviewer and language in the pull-request description. Fluent-speaker review is required before production release.
